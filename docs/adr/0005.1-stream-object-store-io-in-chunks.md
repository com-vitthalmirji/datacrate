# 0005.1. Stream object-store transfers in fixed chunks instead of buffering whole files

## Status
Accepted

## Context
[0005](0005-bounded-pipeline-backpressure.md) established a bounded-memory pipeline for local
CSV→Parquet conversion. Once the pipeline was extended to read from and write to object storage
(see [0004](0004-object-store-io-scope-and-async-shim.md)), follow-up measurements across three
input sizes found peak memory growing linearly with input size — roughly 52 bytes per row — instead
of staying flat. This contradicted the pipeline's bounded design.

The cause traced to the object-store download and upload functions: `download_to_temp` materialized
the entire remote object into one in-memory buffer before writing any of it to disk, and
`upload_from_temp` did the mirror-image thing, reading the whole local file into memory before
uploading. Neither of `thread::scope`'s producer/consumer threads or the channel between them was
at fault — the bounding work from [0005](0005-bounded-pipeline-backpressure.md) was correct; this
was an entirely separate object-store I/O bug.

## Decision
Rewrote both functions to stream in fixed 8 MiB chunks. Downloads fetch the object's size, then
loop ranged `get_range` calls, writing each chunk straight to the local temp file. Uploads stream
the local file through `object_store`'s own multipart writer (`WriteMultipart`, which already
handles the storage backend's minimum part-size requirements) in the same 8 MiB chunks.

## Consequences
Measured peak memory at three input sizes dropped roughly 4x at the largest size tested, and the
growth rate against input size fell from ~52 bytes/row to ~13-14 bytes/row. That remaining slope is
real, not fully flat — the leading hypothesis is allocator high-water-mark behavior in the CSV
parser's per-field string allocations, not a second buffer-the-whole-file bug, though this hasn't
been confirmed with a heap profiler. The pipeline's bounded-memory claim now reflects reality at a
shallower rate than before. Treat "shallower slope, not flat" as the accurate characterization,
not "fixed."
