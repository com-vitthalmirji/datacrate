# 0003.1. Workshop compiler-error exercises live as a sibling to the Rust practice crate's source

## Status
Accepted

## Context
This repository also carries a small set of participant-facing exercises: source files meant to
produce compiler errors intentionally (a "predict the error, then fix it" teaching loop). These
exercises share no code and no build target with the Rust practice crate established in
[0003](0003-rust-practice-crate-isolation.md) - they're not meant to compile as part of any
`cargo build`.

They needed a location. Mixing them into the Rust practice crate's own `src/` would blur two kinds of content - general
Rust practice vs. pedagogy - inside a single source tree, even though
[0003](0003-rust-practice-crate-isolation.md)'s isolation rule is about the dependency graph, not
where files physically sit.

## Decision
Placed the exercises as a sibling directory to the Rust practice crate's `src/`, inside the same crate
(`crates/rusty-ready/exercises/`), rather than merging them into `src/` or keeping them at the
repository root. No new Cargo build target was added - the files are still meant to fail
`cargo build` on purpose.

## Consequences
The exercises get a stable, discoverable home without reopening
[0003](0003-rust-practice-crate-isolation.md)'s isolation guarantee: nothing in `exercises/` is
wired into any Cargo target, so it stays exactly as unreachable from the pipeline crates as the
Rust practice code itself. The one thing this doesn't solve is discoverability from the repository
root - someone skimming top-level directories won't see the exercises directly; that's an accepted
tradeoff of keeping the isolation rule about dependencies rather than directory placement.
