# 0007.1. Force sort-merge join for memory-bounded joins; hash join's build side cannot spill

## Status
Accepted

## Context
[0007](0007-datafusion-resource-control.md) established a memory-bounded execution environment with
spillable operators. Running a large join under that bound surfaced a gap: `HashJoinExec`'s build
side (the `collect_left_input` path, which materializes the smaller join input into an in-memory
hash table) has no disk-spill fallback at all in the pinned DataFusion version - it either fits in
the memory pool or the query fails with `ResourcesExhausted`. Checking the join operator source
directly (`grep -l spill` across the join implementations shows `SortMergeJoinExec` has spill
support; `HashJoinExec` does not) confirms this, rather than inferring from behavior alone.

A join at real scale - large enough that neither input fits in the configured memory pool -
needs a join strategy that can spill. Without one, the memory bound from
[0007](0007-datafusion-resource-control.md) is a bound in name only for any query that joins.

## Decision
For joins expected to exceed the memory pool, explicitly force `SortMergeJoinExec` over the default
hash join by setting `SessionConfig::set_bool("datafusion.optimizer.prefer_hash_join", false)`.
`SortMergeJoinExec` spills correctly under the same `FairSpillPool` from
[0007](0007-datafusion-resource-control.md), where `HashJoinExec` would fail outright on the same
input.

## Consequences
Large joins complete under the configured memory bound instead of failing with
`ResourcesExhausted`, at the cost of sort-merge join's typically higher CPU cost relative to hash
join for inputs that *do* fit comfortably in memory. This is a deliberate, workload-specific
override, not a global default - smaller joins that fit in the memory pool should keep using hash
join's default cost-based selection. A query planner that could choose spillable joins
automatically based on estimated input size would remove the need for this manual override, but
that capability doesn't exist in the pinned DataFusion version.
